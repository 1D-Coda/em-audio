# Test signing credential — not a trust anchor

Everything in this directory is a self-signed credential generated by
`tools/make_test_certs.sh` for one purpose: to let `c2patool` sign and validate
the manifests this repository produces, under a trust anchor declared locally
for the run.

**`ee.pk8.pem` is an unencrypted private key and is committed deliberately.**
It is published so that a reproduction signs with the same identity the results
were produced under, without needing to generate its own. Publishing it costs
nothing, because the key's only power is to sign manifests that validate for
someone who has explicitly chosen to trust `ca.pem`, and nobody does outside
this repository's own pipeline.

To be explicit about what this credential is not:

- it is not on the C2PA Conformance Program trust list, and the manuscript says
  so where it reports the transport results
- it is not issued by any certificate authority, public or private
- no browser, operating system or C2PA consumer trusts it by default
- a manifest signed with it proves only that this test key signed it

Do not reuse this key for anything. If you need a signing identity of your own,
run `tools/make_test_certs.sh`, which regenerates the whole directory. Nothing
in the pipeline depends on these particular files: the frozen fixtures record
the signer's subject name, which the script always produces identically, and no
serial number or fingerprint.
